## 0. 提案の要約

| 項目 | 提案 |
| --- | --- |
| 層化専用量 | **`gt_positive_frame_count`** — 有効なGT陽性点が1点以上存在するframeの異なり数 |
| 揃える対象 | **保存された教師点群でのGT陽性frame数**（9.2.2の二択のうち時間方向）。空間的な大きさではなく、観測時間でもない |
| 層化が働く範囲 | **候補159件からinternal_test 18件を抽出する際の偏り**。validation18は固定で対象外 |
| 単位 | frame（無次元の個数）。**mm換算を要しない** |
| 集約 | 不要。定義上すでに動画単位の量である |
| 追加I/O | **なし**（既に読む配列だけで決まる）。層化量そのものは既存の計数結果を再利用できるが、**入力検査と中央値判定は追加される** |
| 構成可能性の判定 | 3群の中央値が**狭義単調増加**であること |
| 旧目的からの変更 | **あり。** 臨床FLに基づく「大きさの均衡」から「保存された教師点群でのGT陽性frame数の均衡」へ変わる（3.1に明記） |

**この提案の利点は、層化と分割構築を未解決のmm作業から切り離せることである。**
9.2.3のとおりframe数を採る場合はmm換算を要求されないため、
mm/pixelの値取得・動画対応・換算検証の完了を待たずに**工程2a・2bを実行できる。**

ただし**Step 0全体がmm作業から解放されるわけではない。**
工程4（train_coreのmmメタ情報監査、S0-6）と、mm/pixelの供給元・値・動画対応の確認は
Step 0の作業として残る。切り離せるのは層化量の算出と分割の構築・確定である。

## 1. 採用を提案する層化量（9.2.8-1）

### 1.1 名称と位置づけ

**名称:** `gt_positive_frame_count`
**位置づけ:** GT由来の**層化専用量**。
「サイズ代理量」「FL相当量」「代理FL」とは呼ばない。S5-17の正解FL・参照FL・採用済み評価指標として流用しない。

**目的:** **候補159件からinternal_test 18件を抽出する際の偏りを抑える。**
抑える対象は、**保存された教師点群において大腿骨が陽性として記録されたframeの数**である。

3集合全体の均衡ではない。validation 18件は固定で層化の対象外であり、
train_core 144件には固定のtrain sanity 3件が含まれるため、
**「train_core／validation／internal_testの3集合間で均衡させる」とは説明できない。**
層化が働くのは候補159件の中での抽出に対してのみである。

また、大腿骨の大きさの均衡ではない。**fps・strideが159動画で一定であることは未確認であるため、
「観測時間」や「連続した時間範囲」を揃えるとも言えない。** 揃えるのは
「保存された教師点群でのGT陽性frame数」という、点群の記録上の個数である。

### 1.2 算出式

1動画について、教師H5から次を読む。**読み取る対象は既存`read_gt_points`と同じ4配列だが、
変換前に検査する必要があるため同関数は使わない**（3.2.1）。

```
pixel_xy    : point_cloud/pixel_xy
frame_order : point_cloud/frame_order
point_label : annotation/point_label
valid_mask  : annotation/valid_mask
gt_positive := valid_mask AND (point_label == 1)
```

```
gt_positive_frame_count := | { f : ∃ i, frame_order[i] == f かつ gt_positive[i] } |
                         = len(numpy.unique(frame_order[gt_positive]))
```

すなわち**有効なGT陽性点を1点以上含むframeの異なり数**である。

### 1.3 入力・対象集合・集約

| 項目 | 内容 |
| --- | --- |
| 入力 | 教師v7 H5の上記4配列のみ。**中間pseudo-3D H5、臨床FL表、mm/pixel、予測、checkpointを使わない** |
| 対象集合 | 候補159動画（旧train162からtrain sanity 3を除いた集合） |
| frame集合 | 動画内でGT陽性点を持つframe。分母を要しないため、対象frame集合の定義問題が発生しない |
| 集約方法 | **不要。** 定義上すでに動画1件につき1つの整数である。frameごとの値を動画単位へ集約する処理は存在しない |
| 単位 | frame（個数）。座標変換もmm換算も経由しない |

### 1.4 既存実装との関係（追加I/Oが無い根拠と、追加で必要になる処理）

`Stage5/checks/real_h5/check_stage5_gt_component_count.py`の`analyze_video`は、

```python
for frame in np.unique(frame_order[gt]):
    ...
    per_frame.append({...})
...
return {... "num_gt_frames": len(per_frame), ...}
```

としており、**`num_gt_frames`は本提案の`gt_positive_frame_count`と同一の値である。**
`per_frame`は`np.unique(frame_order[gt])`の反復で構築されるため、
`link_distance`にも`min_component_points`にも**依存しない**（コードで確認済み）。

builderは既にmulti-region分類のため同checkerの`analyze_video`を候補159件に対して呼んでおり、
その戻り値の`sweep[0]["num_gt_frames"]`を読むだけで本量が得られる。
**したがってH5の追加読み込みは発生せず、層化量そのものの計算も既存の計数結果の再利用で足りる。**
9.2.6が付した条件（既読配列だけから算出できる場合に限り「追加I/Oなし」が成立する）を満たす。

**ただし「追加計算なし」とは言えない。** 3.2で追加する入力検査、3.3の中央値による成立条件判定、
群割当と配分の検証は新規の計算である。9.2.6のとおり、
**新たな検証・監査更新・テストは必要である**（5章）。

**`read_gt_points`は使用しない（3.2）。** 同関数は検査前に`astype`で変換するため、
不正値が検出されないまま通過し得る。builderは自前の読取り・検査関数で生配列を検証してから
変換し、その結果を`analyze_video`／`classify_video`へ渡す。
**クラスタリングと分類の監査済みロジックは変更せずそのまま再利用し、読み込みも1回のままである。**

### 1.5 他の候補を採らない理由

| 候補 | 採らない理由 |
| --- | --- |
| GT陽性frame率 | 分母の定義が必要になる。9.2.2はGT陽性frameを分母にすることを禁じており、対象frame集合を別途定義しなければならない。**本提案が読む4配列だけでは分母を確定できない**（`frame_order`に現れないframeは、その4配列からは見えない）。`stage5/utils/h5_io.py`は`per_frame_counts`を参照する経路を持つため、他の入力を加えれば総frame数を得られる可能性はあるが、それは追加入力と追加の定義作業を意味する。動画長の影響を一部抑える利点はあるが、定義上の不確かさと入力が増える |
| frame内のGTの空間的広がり | `pixel_xy`は**local crop座標**であり、`local_resize_scale`が動画ごとに異なり得るため、生のcrop pixelでの広がりは**動画間で比較できない**。比較可能にするには中間H5の逆変換情報（追加入力、「追加I/Oなし」が崩れる）が要り、物理量として扱うなら未取得のmm/pixelも要る。**Step 0を未解決のmm作業に依存させることになる**。加えてframeごとの値を動画単位へ集約する方法、複数領域の扱い、外れ点の扱いを新たに定義する必要がある |
| pseudo-3D主軸方向の長さ | 9.2.3のとおり、元frameのx/y mm/pixelが判明してもframe間方向の座標・単位・物理的意味は未確認であり、3D長さを定義してはならない |
| GT陽性点の総数・frame平均 | 点サンプリング密度に直接依存する。frame数はframeあたり1点以上あるかだけを見るため、密度変化に対して相対的に頑健である |

## 2. 影響と今回保証しないこと（9.2.8-2）

**この量は大腿骨の長さでも大きさでもない。** 次の要因の影響を受ける。

| 要因 | 影響 | 扱い |
| --- | --- | --- |
| sweep速度 | 短い大腿骨をゆっくり走査した動画と、長い大腿骨を速く走査した動画が同じ値になり得る。**この量は両者を区別しない** | 保証しない。層化の根拠を「大きさ」と説明しない |
| frame抽出stride・fps | 動画ごとに異なる場合、1 frameが表す時間・距離が変わり、値の意味が動画間で揃わない。**現時点で全159動画にわたり一定であることは未確認である** | 保証しない。2aで、既に開いているH5の属性から`fps`・`stride`が得られる場合に限りprivate記録へ残す。**この確認のために新たなファイルを開かない** |
| 動画長 | 長い動画ほど大きな値を取りやすい。比率を採らないため、この影響は抑制されない | 保証しない。「保存された教師点群でのGT陽性frame数の均衡」であって、「大腿骨の大きさの均衡」でも「観測時間の均衡」でもないと明記する |
| 点サンプリング密度 | frameあたり1点以上あるかのみを見るため、密度の変化に対しては比較的頑健。ただし大幅な間引きでframeの唯一の陽性点が失われれば、そのframeは計数から落ちる（閾値的挙動） | 保証しない。限界として記録する |
| 座標系・crop/resize | **算出に座標値を直接使わない**（`frame_order`とラベルのみで決まる）ため、座標変換の数値誤差は本量へ入らない。**ただしcropやサンプリングが教師点そのものの生成に与えた影響は残る。** crop品質により陽性点が失われたframeは、既に計数から落ちている | 座標変換に起因する誤差は生じない。教師点の生成過程の影響は保証しない |
| 教師の無効化処理 | crop quality／XML invalidationで陽性点が除去されたframeは計数から落ちる。本量は**無効化後の教師状態**を反映する | 仕様として明記する。無効化前の値は算出しない |
| 複数領域 | frame内に何領域あっても1 frameとして数える。**領域数を直接使わないというだけで、multi-region軸との統計的独立を意味しない。** 両軸が相関する可能性はあり、その場合は一部のセルが小さくなる | 仕様として明記する。両軸の独立は保証しない |

**保証しないことの明示:**

- 本量は臨床的な大腿骨長と対応しない。S5-17の代理FL定義の候補ではない。
- **観測時間や連続した時間範囲を揃えるものではない**（fps・stride未確認）。
- 分割後に候補159件とinternal_test 18件の分布が一致することを保証しない。
  小さい層から必ず選出されることも保証しない。
- **中央値の成立条件（3.3）は、退化した三分割を止める事前ルールである。
  群間で値域が重ならないことを保証する条件でも、層化の有効性を保証する条件でもない。**
- 本量による層化が汎化性能や評価の妥当性を改善することを示すものでもない。

## 3. ゼロ・欠損・算出不能・同値・退化の扱いと停止条件（9.2.8-3）

### 3.1 旧目的からの変更の明記

9.2.2の要求に従い記録する。
**D-037および9.2が定めた「臨床FLの三分位による大きさの均衡」は、本提案では「保存された教師点群での
GT陽性frame数の均衡」へ変更される。**
揃える対象が「大腿骨の大きさ」から「保存された教師点群でのGT陽性frame数」へ変わっており、
旧目的をそのまま達成するものではない。**観測時間や連続した時間範囲を揃えるものでもない**（fps・stride未確認）。

### 3.2 値の区別

| 区分 | 定義 | 扱い |
| --- | --- | --- |
| **正常なゼロ** | 4配列が正常に読め、行数も整合し、`valid_mask AND label==1`を満たす点が1つも無い | **有効な値0として順位付けに参加させる。** 欠損扱いにしない。件数をprivate記録へ残す |
| **算出不能** | 3.2.1の検査のいずれかに違反 | **停止。** 0や欠損へ置換しない。該当件数のみを報告し、動画識別情報は共有しない |
| 欠損層 | **本提案では存在しない。** 全候補について値が定義される（算出不能なら停止するため） | `FL_missing`に相当する第4群を持たない。層はmulti-region 2 × 値3群 = 最大6セル |

#### 3.2.1 変換前の生配列に対する検査（必須）

**既存の`read_gt_points`は使用しない。** 同関数は

```python
frame_order = f["point_cloud/frame_order"][:].astype(np.int64)
point_label = f["annotation/point_label"][:].astype(np.int64)
valid_mask  = f["annotation/valid_mask"][:].astype(bool)
```

のように**検査の前に変換する**ため、不正値が黙って通過し得る（動作を確認済み）。

| 入力 | `astype`が起こすこと |
| --- | --- |
| 非整数の`frame_order`（例 3.7） | `int64`へ切り捨てられ3になる。別frameへ併合される |
| `valid_mask`が0/1以外の整数（例 2） | `True`になる |
| `valid_mask`がNaN | **`True`になる** |
| `pixel_xy`が(N,3)等 | `shape[0]`しか見ないため形状違いが通過する |

したがってbuilderは**自前の読取り・検査関数**を持ち、次の順で処理する。

1. 生配列のまま読む（`astype`しない）。
2. 下表の検査を行う。違反は**停止**（0や欠損へ置換しない）。
3. 検査に合格してから明示的に変換する。
4. `{pixel_xy, frame_order, gt_positive}`の辞書を作り、
   **既存の`analyze_video`／`classify_video`へ渡す**。クラスタリングと分類のロジックは変更しない。

読み込みは1動画1回のままで、追加I/Oは発生しない。

| 検査対象 | 検査内容 |
| --- | --- |
| dataset存在 | `point_cloud/pixel_xy`、`point_cloud/frame_order`、`annotation/point_label`、`annotation/valid_mask` |
| 次元 | `pixel_xy`は2次元かつ第2軸が2、他の3つは1次元 |
| 行数 | 4配列の行数が一致 |
| 空配列 | 行数0は**算出不能として停止**（GT陽性frame数0の「正常なゼロ」とは区別する） |
| `frame_order`の型・値 | **有限であること**（NaN・±Infは停止）。整数型であること。浮動小数型の場合は**全要素が整数値と一致し、かつ変換先の整数型（int64）で表現できる範囲内である場合に限り**受理する。**整数値に見えても、Infや範囲外の値は拒否する。** 負値は停止 |
| `point_label`の型・値 | 整数型であること。値域が`{-1, 0, 1}`に含まれること |
| `valid_mask`の型・値 | bool型、または値が`{0, 1}`のみの整数型。**それ以外（2以上、NaN、浮動小数）は停止** |
| 整合性 | `valid_mask == (point_label != -1)`（teacher preflightと同じ不変条件） |
| `pixel_xy`の有限性 | NaN・Infを含まないこと。**`analyze_video`は距離計算に使うため、非有限値はクラスタリング結果を壊す** |

`pixel_xy`の有限性検査は層化量自体には不要だが、
**同じ読み込みをmulti-region分類にも使うため必須**である。

### 3.3 三分割と成立条件

- 分割方法は現行と同一。値と旧train162リスト内indexで整列し、
  低位から`[q+1]*r + [q]*(3-r)`（`q, r = divmod(m, 3)`、端数は低位群優先）で切る。
  `m`は候補件数（本提案では常に159。欠損群が無いため）。
- **同値の扱い:** 現行どおり旧リスト順で振り分ける。
  **境界の同値が複数群へ分かれ得ることを隠さない。** 本量は整数であり同値が多く発生することが
  想定されるため、境界の同値ブロックに属する候補の件数をprivate記録へ必ず残す。
  この件数は共有しない（層別度数に相当するため）。

**成立条件（結果を見る前に固定する）:**

> **3群の中央値が狭義単調増加であること。** すなわち `median(G1) < median(G2) < median(G3)`。

- 満たさない場合は**停止し、管理チャットへ報告して再判断を求める。**
  C案（multi-regionのみ）等への自動変更は行わない（9.2.4）。
- この条件を採る理由: 9.2.4が指摘するとおり、現行の`assign_fl_groups`は全件同値でも
  形式的に3群へ件数を割り当てられる。「3群に件数を割り当てられること」を構成可能性と同一視しないために、
  **3群が値として区別できることを直接検査する**。狭義単調増加は、異なる値が3種類以上あることを含意する。
- **限界（レビュー指摘を反映）:** この条件は**退化した三分割を止める事前ルール**である。
  - **群間で値の重複が無いことを保証しない。** 中央値が単調増加でも、G1の上端とG2の下端が
    同じ値を取ることはあり得る。境界同値ブロックの件数をprivate記録へ残すのはこのためである。
  - **層化の有効性を保証しない。** 3群が値で区別できることを示すのみで、
    抽出後の分布が均衡すること、この層化が評価に資することは示さない。

### 3.4 停止条件（まとめ）

**工程2a（dry run）**

| 中央値が狭義単調増加でない | 停止。再判断を求める。**C案等への自動変更はしない** |
| 候補件数が159でない | 停止 |

## 4. 監査・builder・中間生成物・封印と共有出力（9.2.8-4）

### 4.1 schema版の更新と旧生成物の誤受理防止

| 対象 | 現行 | 改訂 |

v1の記録・中間生成物はschema不一致で**拒否される**。
臨床FL前提の旧監査記録（`complete:false`の部分監査を含む）が新仕様として受理されることはない。

#### 4.1.1 設定の固定と照合（schema版だけでは不十分）

**schemaをv2にしても、設定の異なるv2同士の混用は防げない。**
たとえばdry runを`min_component_points=5`で行い、確定を`=3`で行う、といった取り違えは
schema検査を通過してしまう。したがって次のようにする。

**中間生成物へ固定する設定（dry run時に書き込み、確定時に照合する）**

| 設定 | 内容 |
| --- | --- |
| 層化量の仕様版 | `gt_positive_frame_count` の識別子と版（例 `gt_positive_frame_count_v1`） |
| 成立条件 | 中央値の狭義単調増加（条件の識別子と版） |
| multi-region設定 | `link_distances`、`min_component_points`、判定field（`multi_region_any_frame_all_radii`） |
| 抽出設定 | `SELECTION_METHOD`（`sha256_keyed_sort_v1`）、seed、`internal_test_size`、配分規則 |
| 入力 | **3入力（train list／val list／sanity list）の期待hash**、候補identityの並び。FL表の廃止により入力は3つである |

**確定時（`--confirm`）の扱い:**

1. **中間生成物に記録された設定を唯一の基準とする。**
   対応するCLI引数が与えられ、かつ中間生成物の値と異なる場合は、
   いずれかを黙って優先せず**停止する**。これにより
   「dry runとは別の設定で確定した」状態が成立しない。
2. **CLI引数が省略されていても、実装が対応していない版は拒否する。**
   中間生成物に記録された層化量の仕様版・成立条件の版・抽出方式の版が、
   その時点の実装が扱える版の集合に含まれない場合は**停止する**。
   引数を省略したことが、未知の版を暗黙に受理する理由にはならない。
   実装は対応可能な版を定数として持ち、中間生成物の版と照合する。

この照合は、既存の`--expected_intermediate_sha256`によるファイル指紋照合とは**別の検査**である。
指紋は中間生成物が改変されていないことを示し、本項は
**確定時の設定が中間生成物と同一であること**を示す。

### 4.2 入力監査の改訂

- 臨床FL表に関する引数・検査を**すべて削除する**（`--clinical_fl_csv`、列名、欠損トークン、
  `--defer_clinical_fl`）。改訂後の監査はFL表を持たないため、**分割パスが存在しなくなる。**
- 監査が保証する範囲: 旧train162／validation18リストの読取り・件数・teacher pattern・重複なし・
  相互排他・実在、train sanity 3の動画identityによる確定と旧評価ID mapとの1対1照合、候補159件の導出、
  **3入力（train list／val list／sanity list）の期待hash固定**（FL表の廃止により入力は3つ）。
- **9.2.5-5の区別:** 入力監査は「入力が確定したこと」までを保証する。
  **GT由来量の算出と層構成可能性の検証はbuilderの責務**であり、工程2aで実施する。
  監査記録はその完了を意味しない。
- 既に実行した部分監査（v1、`complete:false`）は履歴として保持する。
  そこで確認した旧リスト・sanity identityの結果は証拠として参照してよいが、
  **v2記録の発行を省略する根拠にはしない**（9.2.5-3）。

### 4.3 builderの改訂

- 臨床FL表の入力・intakeを削除。`classify_clinical_fl`／`assign_fl_groups`／`FL_GROUP_*`を、
  層化専用量に基づく`compute_stratification_quantity`／`assign_stratification_groups`／
  `STRATUM_GROUP_*`へ置換する。**三分割の順位ロジック、最大剰余配分、seed 42、
  SHA-256鍵付き抽出（`sha256_keyed_sort_v1`）、契約検査6項目は変更しない。**
- 層化量はmulti-region計数と同じGT読み込みpassの中で取得する（1.4）。
- 中間生成物へ記録する内容: 候補identity、alias、multi-region分類、**層化量の値**、群割当、
  算出仕様と版、成立条件の判定結果、境界同値ブロック件数、正常ゼロ件数、
  （取得できた場合のみ）`fps`・`stride`、入力hash、来歴。**すべて封印側。**

### 4.4 封印と共有出力

9.2.7に従い、**工程2aの共有出力を縮小する。**

**「共有するGT集計」と「照合・再現のための情報」を区別する。**
前者は件数と真偽のみに限るが、後者は工程の接続に必要なので残す。

| 種別 | 出力 | 共有可否 |
| --- | --- | --- |
| **GT集計** | 候補件数、層構成可能性の真偽 | **可。これだけ** |
| GT集計 | 層別度数（群サイズ）、分布、極値、中央値、動画別の層化量・層割当 | **不可（封印）** |
| **照合・再現情報** | `intermediate_sha256`（dry runが出力し確定へ渡す指紋）、schema版、層化量の仕様版、成立条件の版、multi-region設定、抽出設定、入力hash | **可。GT集計ではない** |
| 封印 | 動画別GT統計、層化量の値、群割当、セル別配分、境界同値件数、正常ゼロ件数、中央値、（取得できた場合の）`fps`・`stride` | 不可 |

- **`intermediate_sha256`は共有側に残す。** 現行の確定処理は
  `--expected_intermediate_sha256`としてこの値を必要とするため、
  これを落とすとdry run→確定の接続が切れる。指紋はGT値を含まない。
- **層別度数（群サイズ）は共有しない。** GT由来量の度数に当たるため。
  これにより、9.2で設計していた「FLの3群サイズを共有する」手続きは完全に廃止される。
- 分布・極値・中央値・動画別値も共有しない。
- 停止時の報告も件数と停止種別のみとし、原因動画の識別情報とGT値を共有ログへ出さない。
- 9.2.7に従い、**算出仕様・実装/schemaの版・入力の来歴・設定・抽出方法はmanifestへ保存し、
  splitの再現と監査のために後続工程へ引き継ぐ。** 引き継ぐのは仕様であって封印された動画別値ではない。

これにより、9.2で設計していた「FL周辺度数をsplit確定前に1回だけ共有する」手続きは**不要になる**。
2a→管理の受け渡しは「候補159件、層構成可能: 真偽」に、
**確定工程へ引き継ぐための`intermediate_sha256`と各仕様版**を添えたものとなる。
