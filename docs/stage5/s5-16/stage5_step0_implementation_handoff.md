## 3. split生成前に確定する仕様

実装担当は以下を具体化し、結果を見る前に1仕様へ固定する。未定義部分を暗黙の既定値で埋めない。

1. **GT multi-regionの定義:** 使用checker・版・出力field・距離と最小点数等の設定を記録する。
   「複数領域frameが存在する」と「複数領域frame割合が閾値以上」を混同しない。
   候補動画の情報が不足する場合、GTのみから算出する対象・CPU量を先に報告する。
2. **臨床FL三分位:** 三分位を計算する母集団、境界の同値・欠損・単位不整合の扱いを明示する。
   validationの臨床FLは読まない。欠損を推定補完したり、都合よく動画を除外して件数を合わせたりしない。
3. **層から18件を配分する規則:** 小さい層・空の層・丸めの扱い、入力順序、乱数器・seedを固定する。
   seed42を候補とするが、S5-16でsplit seedの具体値まで決定済みとは記録しない。
   異なるseedの成績や見栄えを比べる探索は行わない。
4. **実行・封印:** 新規のprivate出力先、入力hash、コードrevision/hash、実施上限と異常停止後の再実行手順を示す。
   正常なsplit確定は1回を基本とし、再生成は理由を報告する。旧リスト・H5は変更しない。

実IDを含むリストは実機private側に保持し、共有側は件数・hash・検査成否だけにする。
internal_testの層別GT統計・FL分布・動画別値を、確定後に人間が読むレポートへ出さない。
split構築中の層化参照と、確定後のデータ封印を区別し、stdout・例外・一時ファイルも同じ境界を守る。

## 4. 封印・漏洩防止

保存する契約はtrain_core／validation／internal_testのリストhash、teacher版、生成仕様・コードhashと封印状態。
相互に素、和集合が旧180動画と一致、train_core＋internal_testが旧train162と一致、sanity保持を確認する。
リストの内容hashと動画identityの照合は既存`stage5/utils/file_list_mode.py`を参照し、
パス表現差を理由に実対象の相違まで許容しない。

通常の学習・評価・方式選択処理は許可リストで対象を制限し、internal_testへのアクセスをH5読込前に拒否する。
既存のdirectory-modeへ暗黙fallbackして封印集合を混ぜない。封印はフラグの保存だけで完了とはしない。
実機でのディレクトリ分離・権限・manifest guard等、既存成果物を壊さず人間の閲覧とコードのアクセスを
制限する具体策を示す。旧checkpointは20cでもinternal_test評価に使えないことを契約に残す。
20cの解除・評価処理そのものを先行実装・実行する必要はない。

合成データで、重複・欠落・件数違い・sanity混入・不正hash・封印集合の要求・旧checkpointの要求・
片側リストのみの指定等が停止することを検証する。正常系の再現性と既存経路への影響も確認する。
実internal_testを読み出して拒否動作を試すのではなく、合成テストとアクセス前guardの証拠を残す。

## 5. train_core専用class weight

参照実装は`Stage5/train_stage5.py`の`compute_class_counts_from_h5()`と
`pointnext_class_weights_from_counts()`。元H5のvalidかつignore以外の点を各動画1回数え、
overlap windowで重複計数しない。現実装の式は`1 / (frequency + epsilon)`、平均weightを1へ正規化しfloat32へ変換する。
W-A共有configに`auto_class_weight_epsilon=0.02`・正規化有効の記録があるが、実機の算出元記録にも照合する。
旧W-Aの固定数値を新splitへコピーしない。

train_core144のリストを明示入力として1回算出する。validation／internal_testや全ディレクトリを数えない。
対象hash、teacher・label policy、算出コードrevision/hash、設定、解決済みweightの精度を記録して固定し、
S5-18〜S5-20のsegmentation lossで同じ値を使う。旧W-Aとの差を見て調整・再探索しない。
既存関数再利用／共通化は最小範囲とし、training mainを起動せずCPUで完結する設計にする。
純粋関数の合成検証で算出式・valid／ignore処理・空集合の停止・対象制限を確認する。

## 6. mmメタ情報とS5-17への開始条件

確認対象はtrain_coreに限定し、validation臨床FL・封印internal_testを読まない。
mmスケールの単位、x/y別の取得可否、動画内一定かframe別か、
`pixel_xy`→`local_resize_scale`／`local_crop_left/top`逆変換→元frame→mmのメタ情報を確認する。
元画像寸法・frame対応の欠落と取得不能を報告し、他動画の値を流用しない。
pseudo-3D Zのmmスケールが確立したとは仮定しない。
ここでは代理FLを計算・選択せず、`T_FL`も推定しない。S5-17実行前の未決事項として引き継ぐ。
