## Core code

Paths below are relative to `Stage5/` (this file lives in `docs/stage5/`).

- `train_stage5.py`: training CLI.
- `infer_stage5.py`: inference CLI.
- `evaluate_stage5.py`: annotated H5 evaluation CLI with window and aggregated metrics.
- `prepare_stage5_evaluation_data.py`: selects evaluation H5 files and collects reference PLY files.
- `summarize_stage5_evaluations.py`: combines metrics from multiple checkpoints.
- `export_anonymized_stage5_metrics.py`: creates shareable split-labeled metrics and a separate private ID map.
- `stage5/`: dataset, model wrappers, losses, metrics, and utilities.
- `stage5/utils/file_list_mode.py`: S5-15 fixed train/val file-list inputs (stdlib only). Validates a saved list pair -- both lists present and readable, non-empty, no duplicates within a list, no train/val overlap, no repeated file name across the union (one video name = one identity for angles and evaluation), every entry existing and matching the teacher pattern, and an optional exact total -- then writes the combined train-then-val manifest that `train_stage5.sh`'s teacher preflight inspects, so the preflight and the training run can never see different file sets. Every failure raises/exits 2 instead of falling back to directory splitting, which is the silent-different-split failure the mode exists to prevent. Also provides `compare_file_lists()`, which separates a genuine content difference (different videos, or a different order) from a mere path-representation difference (same videos under another mount prefix), reporting both `content_sha256` and `identity_sha256` rather than relaxing the comparison until it passes.
- `stage5/utils/rotation_augmentation.py`: S5-15 training-only random Z-rotation augmentation (pure numpy, no torch). The angle for one (video, epoch) is derived deterministically from `(base_seed, epoch, stable_video_id)` via SHA-256 (never Python's `hash()`, which is randomized per process and so would differ between DataLoader workers) seeding a local `numpy` `Generator`, so every window of a video shares one angle within an epoch regardless of worker count or fetch order, and numpy's global RNG (used for shuffling/model init) is never consumed. `stable_video_id_from_path()` uses the file name alone so a different mount prefix or a relative path cannot change the angle. `AugmentationConfig.resolve()` records a concrete `base_seed` (explicit value wins; otherwise `train_seed + 500000`) plus the `seed_source` and the derivation formula for config.json/checkpoints, never a null seed. `rotate_video_points()` returns the input array itself with a `None` angle when the mode is `none`, keeping the disabled path free of any angle derivation. The rotation-matrix convention is bit-identical to the S5-14 supplement-2 coordinate diagnosis (right-handed CCW about +Z, float64 internally, float32 out) so the ±15° range carries the same meaning; that finished S5-14 checker is neither imported by nor modified for this module.
- `train_stage5.sh`: editable training launcher with external data paths. Setting both `TRAIN_LIST` and `VAL_LIST` switches it to S5-15 fixed-list mode: `--train_list`/`--val_list` are passed, `--train_dir` and `--val_fraction` are not (so the seed-based re-split is unreachable), truncation is disabled, `INPUT_DIR` is never scanned, and the teacher preflight inspects the listed files themselves. Setting only one is an error with no fallback. Leaving both unset keeps the historical directory-scan behavior unchanged. `AUGMENTATION`/`AUGMENTATION_ROTATION_DEGREES`/`AUGMENTATION_SEED` select the S5-15 training-only rotation, defaulting to `none`.
- `infer_stage5.sh`: editable inference launcher with external data paths.
- `evaluate_stage5.sh`: fixed train-sanity/full-validation checkpoint evaluation pipeline.
- `export_anonymized_stage5_metrics.sh`: standalone anonymized-metrics exporter for an existing evaluation.

Refuses before doing any work to write under `stage5_runs/` or into a non-empty output directory; writes a private record naming the subset videos and an anonymized shareable one carrying its own privacy self-check. A diagnostic checker in the S5-14 mould (it builds the model and iterates the Dataset itself), not a training path: R0/R1 still run through `train_stage5.sh`.
- `checks/dummy/check_dummy_s5_15_gpu_preflight.*`: CPU-side coverage for the above -- every stop-condition rule against constructed records (two angles in one epoch, an angle frozen across epochs, a missing angle while enabled, an angle while disabled, an augmented validation sample, NaN/Inf/None, a scale change or altered label breaking point correspondence, a none-mode regression), head-of-list subset selection, the privacy self-check, and stage C's entire data path run for real on synthetic H5 fixtures with `--skip_optimization` (both modes, 2 epochs, real DataLoader workers) plus the CLI's refusals and its private/shareable output split. Stage B and stage C's model step need the GPU host and are not covered here.
- `checks/real_h5/check_stage5_checkpoint_identity.*`: compares two checkpoints in one run directory -- SHA-256 first, and only if the files differ does it load both on CPU to compare `state_dict` keys, shapes, dtypes and values. Reports **file identity and evaluation-model identity as separate answers**, because a hash mismatch can come from optimizer state or metadata while every model tensor matches; the three conclusions are `identical_file`, `different_file_same_evaluation_model` and `different_evaluation_model` (`--skip_load` yields `file_differs_model_not_checked` rather than guessing). Loads with the production loader's own call, falling back to `weights_only=False` only when the default raises and recording that fallback in the output. Read-only and CPU-only; written for the approved one-off audit of the historical W-A run's `best.pt` vs `last.pt`, which handoff 6.2 needs in order to know whether epoch 5 and best are the same checkpoint.
- `checks/dummy/check_dummy_checkpoint_identity.*`: synthetic coverage for the above on tiny CPU checkpoints -- byte-identical files concluding without any load, **differing files whose tensors match not being called a different model**, genuinely different weights reported with per-key `max_abs_diff`, missing/extra keys and shape/dtype changes kept apart from value differences, `--skip_load` leaving the model question unanswered, and the audited checkpoints keeping their bytes and mtimes with no file added to the run directory. No CUDA, no real run data.
- `checks/real_h5/run_stage5_s5_15_arm.sh`: launches one S5-15 comparison arm (`ARM=r0` augmentation=none, `ARM=r1` random_z_rotation ±15°) by calling `train_stage5.sh`; there is deliberately no second, Python-direct training path. Every experiment condition is an internal constant rather than a caller-supplied override -- the audited GroupNorm init checkpoint (verified by SHA-256 before launch), W-A's saved train/val lists (validated through `stage5/utils/file_list_mode.py`), `groupnorm`/8 groups, the fixed class weight, 5 epochs, `SAVE_EVERY=1`, and an arm-specific output directory that it refuses to reuse if non-empty. **Because it can start training, it defaults to a dry run**: it validates everything, prints the exact resolved command, and stops; only `CONFIRM_TRAINING=1` actually launches. The `run_` prefix (rather than `check_`) marks it as the one script here that trains.
- `checks/real_h5/check_stage5_rotation_augmentation_ablation.*`: S5-15 P3 -- verifies that the R0 and R1 runs differ *only* in augmentation, then compares their fixed-21-video evaluations. Aggregation only: it never trains and never modifies a run directory. Config parity uses a minimal **allowlist** (`output_dir`, `augmentation`, `augmentation_info`) so every other key -- seed, class weight, norm, `train_list`/`val_list`, epochs, rotation range -- must match exactly rather than hiding behind a broad exclusion; both arms must also show fixed-list mode with no `train_dir`. Checks the shared initialization checkpoint path and SHA-256 (optionally against an expected value), file lists between arms and against a reference run, per-epoch/best/last checkpoint presence, and history epoch counts/finiteness. **Trained-checkpoint hash equality is deliberately not required** -- the arms should diverge, so byte-identical `last.pt` files are flagged as `JUDGE` instead. With both `h5_metrics.csv` files it adds split-pooled metrics derived from summed confusion counts (reusing S5-14's `pooled_confusion_metrics()` unmodified, whose column names already match `evaluate_stage5.py`'s output), per-video paired diffs keeping `median_of_per_video_diffs` and `diff_of_split_medians` separate, improved/worsened/unchanged and TP0 counts per arm, and the ignore-region positive rate kept apart from FP on valid GT. The four pre-registered P3 criteria are reported as `satisfied` / `not_satisfied` / `requires_judgment` with marginal magnitudes flagged; the recall/FPR trade-off criterion is always `requires_judgment` and the overall verdict is always `requires_policy_chat_judgment` -- the script never decides adoption. Writes a private JSON and an anonymized shareable JSON with its own privacy self-check. CPU/JSON/CSV only.
- `checks/dummy/check_dummy_rotation_augmentation_ablation.*`: synthetic coverage for the S5-15 ablation checker (P2 Step 4) -- allowlisted config parity accepting only the intended augmentation difference while catching seed/class-weight/norm/`train_list`/epochs/rotation-range differences, swapped arms and a wrong rotation range, file-list prefix-only differences reported as `JUDGE` versus a changed video set as `FAIL`, the reference-list comparison including its `UNKNOWN` path, trained checkpoints being allowed to differ while byte-identical ones are flagged, pooled metrics computed from summed counts alongside separate median-of-diffs/diff-of-medians, per-arm TP0 counts, criteria that stay `requires_judgment` for the trade-off and `UNKNOWN` when evaluation data is absent (never assumed satisfied), a marginal `+0.04pt` median flagged while still counting as satisfied by the written rule, shareable output stripped of run paths and video identifiers, and a structural check that `run_stage5_s5_15_arm.sh` cannot train without `CONFIRM_TRAINING=1` while the aggregation checker cannot launch a run at all. Pure stdlib fixtures: no torch, no CUDA, no training.
- `checks/dummy/check_dummy_fixed_list_mode.*`: coverage for S5-15 fixed-list inputs (P2 Step 3), in two parts that start no training. The bash half extracts `input_source_args()` from `train_stage5.sh` via `sed` (same approach as `check_dummy_class_weight_tag.sh`, so it cannot drift from the real implementation) and checks mode exclusivity (`--train_dir`/`--val_fraction` absent in fixed-list mode, truncation forced to 0 even when `MAX_*_FILES` are set), the **directory-mode regression** (unset lists still yield the historical `--train_dir`/`--val_fraction`/`--max_*` arguments), and rejection of a one-sided configuration. The Python half covers `stage5/utils/file_list_mode.py`: list order preserved rather than re-sorted, missing/empty/comment-only lists raising instead of falling back, in-list duplicates, train/val overlap and same-name-different-mount entries rejected, non-existent entries and non-teacher-v7 names rejected, the expected total enforced, **three unlisted H5 files added to the directory leaving the resolved target set byte-identical**, the manifest listing train-then-val in order, comments/blank lines/whitespace ignored, the content-vs-representation fingerprint split (prefix-only change, reordering and changed videos all told apart), and the CLI writing a manifest on success while exiting 2 and leaving no manifest on rejection.
- `checks/dummy/check_dummy_rotation_augmentation_dataset.*`: Dataset-side coverage for the S5-15 training-only Z-rotation (P2 Step 2), on synthetic H5 fixtures with real torch DataLoaders on CPU -- `none` mode reproducing `normalize_xyz()`+window slicing bit for bit (the regression guard that keeps R0 comparable), no global-RNG consumption and an untouched cached source array, the derived angle actually applied, every window of a video sharing one angle per epoch while different videos differ, `set_epoch()` changing the angle without rotations accumulating across epochs under `cache_data=True` (returning to epoch 1 reproduces it exactly), features/labels/valid_mask/frame_order/point_indices/window bounds unchanged while only XYZ moves, duplicate file names rejected when augmentation is on but still allowed when off, augmentation refusing to run without normalized points or without any seed, `set_epoch()` input validation, and the **mandatory epoch/worker matrix**: `num_workers=0`, non-persistent workers, persistent workers, and an explicit spawn context, each over three epochs, all agreeing exactly. No CUDA, no real data, no training.
- `checks/dummy/check_dummy_s5_15_p1_manifest_audit.*`: synthetic pass/fail coverage for `check_stage5_s5_15_p1_manifest_audit.py` -- that `values_match()` never treats `1`/`0` as `True`/`False`, that several independent config mismatches are all reported instead of short-circuiting at the first, that an `auto` class-weight mode whose *effective* resolved weight matches is `JUDGE` rather than `FAIL` (and a `manual` mode resolving to a different weight is `FAIL`), that duplicate basenames across two mount prefixes fail the `stable_video_id` precondition, teacher-suffix/line-count checks, init-checkpoint SHA-256 taken from the config path (with an unreachable file reported `UNKNOWN`, not `FAIL`), a 5-epoch run without `checkpoint_epoch_*.pt` reported `JUDGE` with `save_every` shown, history epoch-count/NaN detection, and that the shareable summary drops real paths and per-file lists while the private one keeps them (both verified against the timestamp-style-video-ID and absolute-host-path privacy patterns). Pure stdlib: no numpy/h5py/torch/CUDA (S5-15 P1).
- `checks/real_h5/check_stage5_s5_15_p1_manifest_audit.*`: S5-15 P1 -- read-only audit of one `train_stage5.py` run directory (the W-A reference run) against the S5-15 fixed-condition table. Writes a private JSON (real paths/filenames, keep on the training host) and an anonymized shareable JSON (counts, hashes, statuses) carrying its own privacy self-check. CPU/JSON/text only, no torch/h5py/CUDA, starts no training, and modifies nothing inside the audited run directory.
