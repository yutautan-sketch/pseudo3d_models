# Stage5 File Layout

## Current implementation handoff

- `stage5_revision_management_record.md`: authoritative Stage 5 overview,
  chronological revision record, accepted decisions, current status, and next
  implementation order. Start here when deciding what work comes next.
- `stage5_overlap_aggregation_handoff_prompt.md`: current teacher v6 state,
  overlap aggregation diagnostics, BatchNorm parity steps, privacy rules, and
  completion criteria for the next implementation chat.
- `stage5_overlap_aggregation_implementation_policy.md`: implementation-chat
  rationale behind the handoff prompt's overlap aggregation checker design
  (module reuse, accumulator math, mean baseline parity method, output
  layout, and the F1-F3 design decisions). The handoff prompt is authoritative
  if the two disagree.
- `stage5_pointnext_s_training_evaluation_report.md`:
  authoritative investigation history and current findings.
- `TRAINING_IMPROVEMENT_PLAN.md`: earlier planning history; use the evaluation
  report for detailed evidence and `stage5_revision_management_record.md` for
  the current priority order.

## Core code

Paths below are relative to `Stage5/` (this file lives in `docs/stage5/`).

- `train_stage5.py`: training CLI.
- `infer_stage5.py`: inference CLI.
- `evaluate_stage5.py`: annotated H5 evaluation CLI with window and aggregated metrics.
- `prepare_stage5_evaluation_data.py`: selects evaluation H5 files and collects reference PLY files.
- `summarize_stage5_evaluations.py`: combines metrics from multiple checkpoints.
- `export_anonymized_stage5_metrics.py`: creates shareable split-labeled metrics and a separate private ID map.
- `stage5/`: dataset, model wrappers, losses, metrics, and utilities.
- `train_stage5.sh`: editable training launcher with external data paths.
- `infer_stage5.sh`: editable inference launcher with external data paths.
- `evaluate_stage5.sh`: fixed train-sanity/full-validation checkpoint evaluation pipeline.
- `export_anonymized_stage5_metrics.sh`: standalone anonymized-metrics exporter for an existing evaluation.

## Check and debug scripts

`check_*.py` and `check_*.sh` are smoke tests or visualization helpers. They are
grouped under `checks/` so they stay separate from the regular training and
inference launchers.

Main groups:

- `checks/dummy/check_dummy_*`: synthetic H5/model checks.
- `checks/visualization/check_window_batch_ply_export.*`: frame-window DataLoader PLY export.
- `checks/s3dis/check_s3dis_*`: official PointNeXt/S3DIS checkpoint and data checks.
- `checks/transfer/check_s3dis_to_stage5_pointnext_s_transfer.*`: partial S3DIS-to-Stage5 weight transfer.
- `checks/real_h5/check_real_h5_pointnext_s_transfer_forward.*`: real Stage5 H5 forward/PLY check.
- `checks/real_h5/check_stage5_batch_integrity.*`: Dataset/window/point_indices audit against source H5 (S5-04).
- `checks/real_h5/check_stage5_padding_parity.*`: zero-padding sensitivity for logits/gradient/BatchNorm (S5-05).
- `checks/real_h5/check_stage5_overlap_aggregation.*`: overlap-window probability/aggregation comparison (S5-08, 実装事項A).
- `checks/real_h5/check_stage5_batchnorm_mode_parity.*`: eval()/train() BatchNorm probability parity (S5-09, 実装事項B).
- `checks/real_h5/check_stage5_batchnorm_recalibration.*`: diagnostic BatchNorm running-statistics recalibration from the training split, compared against the original checkpoint (S5-10). Saves a diagnostic checkpoint under `stage5_debug/`; never overwrites the original and is never shared.
- `checks/dummy/check_dummy_pointnext_s_groupnorm.*`: BatchNorm-default backward-compatibility and GroupNorm structural/train-eval-parity checks for the PointNeXt-S wrapper's `pointnext_norm` option (S5-11). `--self_test` is CPU-only; the full run needs CUDA and dummy H5 data only.
- `checks/transfer/check_stage5_batchnorm_to_groupnorm_transfer.*`: transfers the existing Stage5 BatchNorm S3DIS partial-init checkpoint's trainable parameters (conv/linear/head/norm affine) into a freshly constructed GroupNorm model, excluding only BatchNorm running buffers (S5-11). Saves `stage5_pointnext_s_s3dis_partial_init_groupnorm.pt` alongside the existing BatchNorm partial-init checkpoint.
- `checks/dummy/check_dummy_label_policy.*`: synthetic BBox non-contour label-policy tests -- pure-array geometry/no-op/fail-fast tests plus a Dataset-level integration test on a hand-built H5 (S5-12, Step E2). No CUDA needed.
- `checks/real_h5/check_stage5_label_policy_bbox_preflight.*`: audits every teacher v6 H5 in the train/val lists for the BBox non-contour label-policy contract (every ignore point lies inside a stored BBox) before enabling `--label_policy bbox_noncontour_background` (S5-12, Step E3). CPU/h5py only.
- `checks/real_h5/check_stage5_label_policy_dataset_parity.*`: confirms on real teacher v6 H5s that switching `--label_policy` changes only labels/valid_mask at audited target points, with everything else (points/features/frame_order/point_indices/window bounds) identical (S5-12, Step E4). CPU/h5py only.
- `checks/real_h5/check_stage5_label_policy_ablation_eval.*`: evaluates one Run A/B label-policy checkpoint against three common targets (`canonical_v6` with a mean-baseline parity gate against plain `evaluate_stage5.py`, `bbox_noncontour_as_background`, `bbox_noncontour_region`) from a single model forward per H5 (S5-12, Step E7). Optional `--export_ply_alias`/`--ply_output_dir` writes GT/prediction diagnostic PLYs (Step E8).
- `checks/dummy/check_dummy_class_weight_tag.*`: synthetic test of `train_stage5.sh`'s `class_weight_tag()` run-naming function (auto/manual/none -> filesystem-safe tag), extracting the function body directly from `train_stage5.sh` via `sed` so it cannot silently drift from the real implementation (S5-13, Step F3). Bash-only, no Python/CUDA needed.
- `checks/dummy/check_dummy_class_weight_ablation.*`: synthetic pass/fail coverage for `check_stage5_class_weight_ablation.py`'s comparison logic (config parity, file-list parity, resolved-weight checks, history finiteness/epoch-count, evaluation target parity) using hand-built JSON/CSV fixtures (S5-13, Step F3). No CUDA/H5/real run data needed.
- `checks/real_h5/check_stage5_class_weight_ablation.*`: config-parity and completion checks between the W-A (control) and W-B (moderate fixed weight) class-weight ablation training runs -- file-list/config/resolved-weight/history parity, initialization-checkpoint path+SHA-256 match, and optional evaluation-target point-set parity from two `evaluate_stage5.py` `h5_metrics.csv` outputs (S5-13, Step F3/F4/F7). CPU/JSON/CSV only, no torch/h5py/CUDA.
- `checks/dummy/check_dummy_class_weight_threshold_free.*`: synthetic pass/fail coverage for `check_stage5_class_weight_threshold_free.py`'s threshold-free curve math (AUPRC vs a hand-verified textbook value, AUROC, tie handling, empty-positive-class NaN, max-F1-from-curve vs grid search, fixed-FPR lookup, threshold-0.5 parity gate) plus a brute-force cross-check across random trials (S5-13補足, Step 3). Pure numpy, no CUDA/H5/real run data needed.
- `checks/real_h5/check_stage5_class_weight_threshold_free.*`: threshold-free (AUPRC/AUROC/PR curve/score-percentile/fixed-FPR) diagnostics for one class-weight arm's checkpoint evaluation, reusing `evaluate_stage5.py`'s already-saved per-H5 prediction `.npz` (`prob_femur`) instead of re-running the model, with GT read directly from the source H5 (S5-13補足, Step 6). Fail-fasts if recomputed threshold-0.5 TP/FP/TN/FN disagree with the existing `h5_metrics.csv`. h5py/numpy only, no torch/CUDA (`evaluate_stage5.py` is intentionally not imported to avoid pulling in torch).
- `checks/dummy/check_dummy_frame_spatial_overlap_diagnostics.*`: synthetic pass/fail coverage for `check_stage5_frame_spatial_overlap_diagnostics.py`'s shared primitives (`find_runs`, per-frame label counts, window-occurrence counts, relative frame decile, class exposure multiplier, duplicate/missing-point and nonfinite fail-fast) plus a hand-built-H5 integration test of the Step H2 GT/exposure audit (S5-14, Step H1). No CUDA needed.
- `checks/real_h5/check_stage5_frame_spatial_overlap_diagnostics.*`: teacher v7 GT + structural training-window-exposure audit -- per-video frame range/count, per-frame positive/background/ignore counts, per-class unique-point vs. window-occurrence-total exposure multiplier, positive-frame run lengths/gaps, frame-relative-decile exposure (S5-14, Step H2). No CUDA needed.

- `checks/dummy/check_dummy_per_window_context_diagnostics.*`: synthetic pass/fail coverage for `check_stage5_per_window_context_diagnostics.py`'s torch-free logic -- the no-tolerance parity gate against a saved W-A prediction (vote-count mismatch, training-occurrence-vs-this-run's-vote_count mismatch, threshold-0.5 predicted-class mismatch, tampered `h5_metrics.csv` row), vote-count bucketing, stratified group summaries, TP/FP/FN/TN classification (confirming ignore-index points are excluded from all four), per-bin exposure/disagreement aggregation, and the Step H3.1 recurrence-cross-check join. No CUDA/torch needed (this module never imports torch at module scope).

Verifies the freshly re-derived mean-probability aggregate against the saved W-A `evaluate_stage5.py` prediction with **no tolerance** (vote_count array equality, training-window-occurrence-count vs. re-inference vote_count equality, and threshold-0.5 predicted-class equality; any mismatch, including CUDA non-determinism, stops the run and is never silently accepted) (S5-14, Step H4). Produces stratified point-level summaries (by GT class / TP-FP-FN-TN / relative-frame-decile / vote-count bucket) and a per-XY-bin exposure/disagreement table that can be joined against Step H3.1's `xy_temporal_recurrence.csv` to test whether unmatched-run recurrence concentrates at high exposure/disagreement bins.
- `checks/dummy/check_dummy_s5_14_summary_export.*`: synthetic pass/fail coverage for `check_stage5_s5_14_summary_export.py` -- frame-position-decile aggregation (excluding undefined/empty-string recall from the mean rather than treating it as 0), the Step H3/H4 `video_summary.csv` merge (including a mismatched-key-set rejection), vote-count-stratified error-rate aggregation (cross-checked against hand-computed values), and the bundle privacy self-check (timestamp-like video ID / absolute host path rejection). Pure CSV/JSON, no h5py/torch/CUDA.
- `checks/dummy/check_dummy_s5_14_supplement.*`: synthetic pass/fail coverage for `check_stage5_s5_14_supplement.py` -- denominator-carrying XY-bin FPR/recall (a 10x raw-FP-count difference collapsing to an identical FPR once the valid-background denominator is applied, and a genuine FPR difference that survives equal denominators; valid/ignore separation; null-with-availability-flag for zero-denominator/empty bins), bin-sum-vs-`h5_metrics.csv` parity (including a tampered-row rejection), train-only XY prior construction with train-sanity self-exclusion (a video outside the train list is left unmodified), the two prior definitions (`raw_count` vs. valid-point-normalized `rate`, with `rate` left `NaN` only where the train denominator is itself 0), hot/cold quantile classification (inclusive tie boundaries, and an `undefined_boundary_collision` report -- never an arbitrary split -- when q75==q25), hot/cold FPR comparison (a cold-FPR-of-0 case that leaves the ratio undefined while the diff stays defined), the (time-half x vote-count) joint stratification table (confirmed to be the true joint cell counts, not a marginal product), within-video paired first-half/second-half recall (one-sided-GT video excluded with a reason, not silently zero-filled or pooled across a differently-composed video set), the point-weighted-vs-frame-equal-weight recall distinction, a hand-built H5+prediction integration test through the structural (no-re-inference) `vote_count` parity gate, and a full CLI privacy/alias check (S5-14補足, Step S1-S5). No CUDA/torch needed.

Pure h5py/NumPy, no torch/CUDA import anywhere in this module.

The one additional GPU forward pass per (video, condition) this diagnosis allows lives only in `run_condition_forward`/`main()` (function-local `torch` import); every other function is torch-free.
- `checks/dummy/check_dummy_coordinate_transform_reconciliation.*`: synthetic pass/fail coverage for `check_stage5_coordinate_transform_reconciliation.py` -- that point-weighted pooling of summed confusion counts is a genuinely different statistic from a naive mean of per-video rates (a tiny video at 100% FPR pooled with a huge video at 0% FPR does not average to 50%), that all-zero-denominator pooled rates stay `None`, that `median_of_per_video_diffs` and `diff_of_split_medians` are confirmed to diverge on a constructed case (one video jumps a lot, the rest stay flat: the median-of-diffs stays near 0 while the diff-of-medians moves), and the two fail-fast consistency checks (duplicate/missing `video_alias` per split×condition, identity's own diff columns must be exactly 0.0). No CUDA needed -- this module is pure CSV/JSON re-aggregation with no torch import anywhere (S5-14補足3).

No re-inference, no new training, no new conditions/videos. Fail-fasts if any split×condition doesn't have exactly the expected distinct video count (duplicate/missing `video_alias`) or if identity's diff against itself isn't exactly 0.0 for every already-saved `*_diff` column.
